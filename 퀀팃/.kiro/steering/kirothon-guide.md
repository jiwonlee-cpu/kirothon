# Kirothon 해커톤 가이드

## 해커톤 주제
**"나"에서 시작하는 업무 혁신**
- 회사에서, 팀에서, 프로젝트에서 내가 매일 겪는 진짜 문제를 하나 골라 Kiro로 해결
- 앱, 워크플로우 자동화, Kiro 에이전트 설계 등 형태는 자유
- 핵심 조건: 내일 당장 내 업무에 적용 가능할 것
- 보너스: 옆자리 동료도 함께 쓸 수 있으면 더 좋음
- 가장 완성된 결과물이 아닌, 가장 좋은 문제를 찾고 해결한 팀이 승리

## 핵심 구조
- `docs/project-idea.md`: 아이디어 및 문제 정의
- `.kiro/specs/`: 요구사항, 설계, 태스크
- `project/`: 실제 구현 코드

## 평가 기준
1. **문제 정의** (최우선) - 해결하고 싶은 문제는 무엇인가? 문제의 중요성과 영향력
2. **개발 과정** - Kiro를 어떻게 활용했나? (MCP, Hooks, Steering, Specs 등)
3. **결과물** - 결과물의 완성도와 확장 가능성

## 심사위원 구성 & 전략
- AWS 리더, Account Manager, GTM팀 + 개발 → 비즈니스/고객 관점 중심
- 개발 편향이 아닌 심사위원 구성 → 기술 깊이보다 문제 정의와 해결 스토리가 핵심
- 이전 유사 해커톤 1등: 기획자 팀 → 코드 완성도보다 "왜 이 문제인가"가 승부처
- 전략: 문제 정의 60% + Kiro 활용 스토리 25% + 데모 15%

## 개발 원칙
- 문제 정의와 해결 방법의 스토리텔링에 가장 많은 시간 투자
- 내가 매일 겪는 진짜 문제에서 출발 → 공감할 수 있는 문제여야 함
- Kiro 기능을 최대한 활용 (Specs, Hooks, Steering, MCP, Sub-Agents)
- 개발 과정을 기록하여 "Kiro를 이렇게 활용했다" 스토리 구성
- 내일 당장 적용 가능한 실용적 결과물 지향
- 심사위원이 비개발자 포함 → 데모는 직관적이고 시각적으로

## 언어
